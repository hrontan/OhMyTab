# ドメイン単位の閉鎖・抽出

通常の「同じサイト」操作は、HTTP／HTTPS URL のホスト完全一致で対象を選ぶ。詳細メニューは、選んだホスト自身と、その直下または深い階層のサブドメインを対象にする。

| 選択したホスト | タブのホスト | 通常 | 詳細 |
| --- | --- | --- | --- |
| example.com | example.com | 対象 | 対象 |
| example.com | a.example.com | 対象外 | 対象 |
| example.com | notexample.com | 対象外 | 対象外 |
| example.com | example.com.evil.example | 対象外 | 対象外 |

固定タブを除外する。各操作の現在ウィンドウ／全ウィンドウ設定を維持する。ポート、パス、クエリー、HTTP と HTTPS の違いはホストの一致に影響しない。

## URL とホストの扱い

- URL パーサーで解釈できる HTTP／HTTPS URL のみを扱う。URL 不明、無効 URL、`file:`、`about:`、`data:`、`ftp:` は対象外とし、空ホスト同士を一致させない。
- ホストは URL パーサーの小文字・国際化ドメイン・IP アドレスの正規化に従う。DNS ホストの各ラベルは英数字で始まり、終わり、内部のハイフンを許す。各ラベルは63文字以下、全体は253文字以下とする。
- 末尾のドット1個は除去し、`example.com.` と `example.com` を同じホストとして扱う。空ラベルやドットが連続するホストは対象外とする。
- IPv4、IPv6、`localhost` など単一ラベルのホストは通常操作の完全一致だけを許す。詳細メニューの候補を生成しない。IPv6 は URL パーサーが正規化した角括弧付きの表記で比較する。

## 詳細メニューの階層

公開サフィックスを含むラベル数を末尾から数え、その手前までの候補を最も具体的なホストから順に列挙する。サフィックスそのものを候補にしない。

| URL のホスト | 候補 |
| --- | --- |
| a.com.b.com | a.com.b.com、com.b.com、b.com |
| a.example.co.uk | a.example.co.uk、example.co.uk |
| co.uk | なし |
| a.tenant.blogspot.com | a.tenant.blogspot.com、tenant.blogspot.com |

ICANN と PRIVATE の両方のサフィックスを導入済み `tldts` で判定する。PRIVATE を含めることで、共有サービスの別テナントまで対象を広げない。API の設定は [tldts の公式説明](https://github.com/remusao/tldts/blob/master/packages/tldts/README.md)に従う。判定表の更新は依存関係の更新時に反映される。

既存メニューは各操作5件で、`l0`〜`l4` に対応する。候補が多い場合は**最も具体的な5階層**を表示し、広い上位階層を省く。例えば `a.b.c.d.e.f.example.com` の候補は、`a.b.c.d.e.f.example.com`、`b.c.d.e.f.example.com`、`c.d.e.f.example.com`、`d.e.f.example.com`、`e.f.example.com`。`f.example.com` と `example.com` は表示しない。

`getDomain` は対象外なら空文字を返す。`isDomainMatch` の比較先は、この関数で正規化したホスト、または階層候補を渡す。詳細閉鎖は既存の `ohmytab_close_l0`〜`l4`、抽出は `ohmytab_extract_l0`〜`l4` を使う。メニューの更新制御と公開済みの対象範囲は[設定同期の説明](settings-sync.ja.md#メニューとバッジへの反映)を参照する。

## 通常・プライベートとコンテナの操作範囲

ボタン、ショートカット、メニューの操作は、要求元のタブの通常／プライベート状態を最初に固定します。「全ウィンドウ」もこの状態が同じウィンドウだけを対象とし、通常とプライベートの間でタブを閉じたり移動したりしません。メニューでは最後にフォーカスされたウィンドウではなく、実際にクリックしたタブを要求元とします。新しいウィンドウへの抽出も要求元のプライベート状態を引き継ぎます。固定タブは操作対象から除外したまま、そのタブから要求した場合のセッション判定には使います。

Firefoxでは、要求元と同じ `cookieStoreId` を持つタブだけを処理します。同一URLでも異なるコンテナのタブを重複と見なさず、同一ドメインの閉鎖・抽出、集約、並べ替え、再読み込みもコンテナをまたぎません。既定コンテナとプライベート用のコンテナも区別します。Chromeではコンテナの条件を適用せず、通常／プライベートの区別を適用します。

要求元のプライベート状態を取得できない場合や、Firefoxで要求元のコンテナIDを取得できない場合は、その操作を実行せず失敗を通知します。他のタブの状態やコンテナIDが不明な場合は、そのタブを対象に含めません。取得できない値を通常ウィンドウや既定コンテナと推定しない方針です。タブ一覧等のAPIが拒否された場合も操作前に失敗を通知し、次の操作を受け付けられるよう実行状態を解放します。

対応下限のFirefoxでは `tabs.Tab` のコンテナIDの読み取りに `cookies` 権限を追加する必要はありません。コンテナを指定してタブを新規作成する場合の権限条件は別です。本機能は既存タブを対象とし、コンテナの作成やCookieの読み出しは行いません。[Mozillaのコンテナ解説](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Work_with_contextual_identities)を参照してください。

## 保護条件と重複タブの優先順位

設定画面で、保護するホスト名、音声再生中のタブの除外、既存グループに属するタブの除外を選べます。初期値は保護ホスト名なし、音声・グループの除外はOFFです。固定タブの除外と前節の通常／プライベート・コンテナ境界は、これらの設定にかかわらず維持します。ボタン、ショートカット、メニューは同じ条件を使います。閉鎖だけでなく集約、抽出、並べ替え、グループ操作、再読み込みも対象です。

保護ホスト名は1行に1件、空行を除いて100件、入力全体で4096文字までです。前後の空白を除き、大文字・小文字、末尾のドット、国際化ドメイン名を通常のホスト名として正規化します。URL、ポート、パス、ワイルドカードは受け付けません。`example.com` はそのホストと `a.example.com` を保護しますが、`notexample.com` は保護しません。`foo.github.io` の指定で別利用者の `bar.github.io` を保護対象に含めることもありません。不正な入力は保存前に拒否し、保存済みの不正な指定を検出した場合もタブ操作を始めません。

操作対象は、最初にセッション境界で絞り、次に保護条件を除外し、その後に機能ごとの対象を選びます。保護理由が重なる場合はすべて保持し、どれか一つでも該当すれば除外します。残す重複タブの選択によって保護を解除しません。このため、保護された同一URLのタブと、操作対象の同一URLのタブが複数残る場合があります。

重複タブは、操作対象の現在の走査順で最後のタブを残すのが既定です。「表示中のタブを優先する」を選ぶと、同じURLの対象のうち要求元のアクティブタブ、最後のアクティブタブ、最後のタブの順で残すタブを選びます。保護タブや別セッションのタブは、この選択に参加しません。

グループ全体を移動すると保護タブも動いてしまうため、同じグループに保護タブがある場合、そのグループのグループ化・グループ移動を省きます。「グループに入っているタブを保護する」がOFFなら、保護されていないメンバーに対する個別の閉鎖や再読み込みは通常どおり対象になります。保護理由の判定は共通関数にまとめており、確認画面でも同じ判定を使用します。

## 実行前の確認

設定の「実行する前に、対象のタブを確認する」を有効にすると、アイコン、ショートカット、コンテキストメニューの操作は、まず確認画面を開きます。既定は無効で、従来どおり直接実行します。確認画面には対象タブのID・タイトル・URL・件数・適用理由とウィンドウ範囲、保護条件による除外理由を表示します。確認画面は要求元と同じウィンドウに開き、固定タブ、別のプライベート／コンテナーセッション、確認画面自体は操作対象にしません。

「キャンセル」では作業タブを閉じたり移動したりしません。「確定して実行」では元の対象IDだけを処理し、確定前にタブと設定を再確認します。対象の増減、URL・ウィンドウ・保護状態などが変わっていれば実行せず、操作のやり直しを求めます。確認画面へフォーカスが移っても、重複時の保持には要求時のアクティブタブを使います。

確認内容はメモリに1件だけ保持し、有効期間は最長60秒です。次の確認を開くかバックグラウンドが停止・再起動すると期限前でも失効し、同じ確認内容を二重に実行できません。確認のためのURL履歴は保存しません。実行途中の変更やAPI失敗では一部だけが実行される場合があるため、拡張機能アイコンの結果も確認してください。

## 閉じたタブの復元と記録の削除

設定画面の「閉じたタブを元に戻す」から、記録できた閉鎖を確認できます。対象は、通常・既定セッションでこの拡張機能が閉じ、現在存在しないと確認できたHTTP(S)タブです。プライベート、Firefoxの非既定コンテナーや不明なセッション、認証情報を含むURL、4096 UTF-16コード単位を超えるURL、内部ページ、ファイルなどは記録しません。すべての閉鎖を元に戻せる機能ではありません。

記録するのはURL、閉鎖直前のウィンドウIDと位置です。元の通常ウィンドウが現存する場合に、新しい非アクティブなタブとしてURLを開き、記録位置を指定します。位置は現在のタブ数に合わせて調整されるため、完全に元の配置へ戻る保証はありません。元のウィンドウがない場合は、別のウィンドウを作らず記録を残します。フォーム入力、閲覧履歴、スクロール位置、グループ、元のタブIDは復元できません。

保持するのは直近の記録対象の閉鎖1回分で、最大50タブ、最長5分です。バックグラウンドのメモリだけを使い、停止・再起動では期限前でも消えます。local／sync領域には保存せず、期限には記録を削除します。画面から個別または全件の削除もできます。対象外の閉鎖では、以前の記録を新しい記録に置き換えません。

部分的な閉鎖失敗では、成功して存在しなくなったと確認できたタブだけを記録します。復元も成功した項目だけを消費し、開始前の失敗は期限内に再試行できます。作成開始後に応答を失った場合などは、作成済みの可能性があるため記録を「作成結果が不明」として保持し、二重作成を防ぐため再試行しません。実際のタブを確認してから記録を削除してください。
