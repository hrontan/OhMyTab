# 設定の保存と外部変更の優先方針

設定画面は入力中の下書きと保存済み設定を分けます。下書きと保存queueは `src/options/options-save.ts`、表示は `src/options/options-form.ts`、保存先とJSONの確認操作は `src/options/options-transfer.ts` が担当します。`input` イベントで編集項目を記録し、`change` イベントまたはエラー通知の「もう一度試す」で保存します。保存は同じ画面内で直列に実行し、待機中の連続変更は最新の下書きへまとめます。古い保存完了でフォーム全体を戻さず、その保存に対応した項目だけを確定します。

## 編集中の競合

別の画面やブラウザー同期による `storage.onChanged` は、未編集項目へ反映します。編集項目への外部変更は下書きを上書きせず、画面に「ほかの設定画面や端末でも設定が変更されました。この画面の入力は残しています。保存すると、この画面で編集した内容を優先します。」と表示します。次に保存する際は編集項目だけを書き込むため、別の項目に届いた外部変更を古いフォーム全体で戻しません。下書きの保存が成功した後は編集状態を解除し、それ以降の外部変更を通常どおり反映します。

「タブを一つのウィンドウにまとめる」(`glue`) と「現在のウィンドウだけを操作する」(`currentonly`) は相互排他です。この2項目は一つの編集・競合単位として扱います。片方を編集すると、変更していないもう片方も下書きの値を保持し、保存では2項目をまとめて確定します。

たとえば `glue:false/currentonly:true` を編集中に外部の `glue:true` が届いても、下書きは `false/true` のままです。競合を通知し、保存時にその組を優先します。逆方向の `true/false` も同じ方針です。両方を同時に有効にした不正な入力には、[共通設定正規化](../src/settings/setting.ts)の既存制約を適用し、`glue:true` のときは `currentonly:false` にします。正規化の制約を解除して下書きを保持するものではありません。

保存失敗は保存済みとして確定せず、下書きと編集状態を残してエラーを表示します。外部変更は未編集項目に反映できますが、競合する組は保存成功まで保持します。利用者は入力を修正するか「もう一度試す」で保存できます。別端末の書き込みをロックするものではありません。保存が完了して編集状態が解除された後は、外部の新しい値が優先されます。

## URLルールの保存先

「URLの条件を保存する場所」では、URL照合の有効・無効（`urlmatch`）とパターン文字列（`urlmatch_pattern`）の2項目を、従来のsyncからこの端末のlocalへ移せます。初期状態では既存のsync値をそのまま使います。保護ドメインや他の設定はsyncに残ります。Firefoxで非表示のChrome専用設定も移行対象にしません。

切替前に画面の保存処理を待ち、未保存の編集を保存します。保存エラーが残る場合は切り替えず、下書きを保持します。同じ拡張origin内の画面・workerによるルール保存と移行は、専用のWeb Lockで直列化します。別端末の同期更新はこのロックの対象外です。

syncからlocalへ移す場合は、localへ候補snapshotを書いて読戻しを確認し、localを有効にして再確認した後でsyncの対象2キーだけを除去します。移行先の準備が失敗したらsyncを使い続けます。切替後の除去に失敗した場合や、除去前の再確認で新しいsync値を検出した場合は、localを使いながらsyncの残存を表示します。確認と除去は一つの原子的な操作ではないため、その間に別端末から届いた更新を除去する場合があります。「同期先に残ったURL条件を削除する」で再試行できます。この明示的な除去では、別端末から届いた新しい値も削除します。ブラウザー提供元のバックアップや他端末のコピーまで消去する保証はありません。

localからsyncへ移す場合は、localのルールをsyncへ書いて読戻しを確認してから保存先を切り替えます。既存のsync値はlocalの値で置き換わります。書込み・確認・保存先の切替が失敗したときは、localの元snapshotを保持します。失敗した処理の途中でコピーが残る場合があるため、表示された保存先と残存通知を確認してください。

Web Locksを使えない環境では切替を無効にし、理由を表示します。既存ルールの読取りと従来のsync設定は継続できますが、localルールの書込みは安全のため失敗として通知します。互換情報では[Navigator.locks](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/locks)と[WorkerNavigator.locks](https://developer.mozilla.org/en-US/docs/Web/API/WorkerNavigator/locks)はChrome69・Firefox96以降で、宣言最小版Chrome123・Firefox112より前です。最小版そのものを実行した証拠とは区別します。

## 設定JSONの入出力

設定画面の「コピーする設定を表示」で、保存済みの設定をコピーできるJSONとして表示します。形式は`ohmytab-settings`、`version: 1`で、既知の28項目をすべて含みます。URLパターンと保護ドメインには機密の名前やアドレスが含まれる場合があります。共有先・保存場所を確認してください。閲覧履歴、閉じたタブ、復元やプレビューの記録・token、実行状態、保存先の選択、復旧用コピーは出力しません。

入力はUTF-8で64KiBまでです。JSONの破損、旧・未知の形式やversion、項目の不足・追加、型・選択肢・数値範囲の不正、相互排他項目の矛盾を、適用前に拒否します。URLルールの既存容量上限と、有効時の構文制約、保護ドメインの制約も適用します。URL照合が無効な場合に保存文字列を実行時に解析しない契約は変えません。

「貼り付けた設定を確認」では、現在値と取込後の値を全項目表示します。確認した内容を明示的に適用するまで書き込みません。キャンセルでは保存済みの設定を変えません。確認後に入力・設定・保存先が変わった場合は、再確認が必要です。未保存の下書きや保存エラーがある場合も、下書きを上書きせず先に保存の解決を求めます。

URLルールは現在選択中のlocalまたはsyncへ取り込み、保存先を変更しません。他の設定はsyncへ取り込みます。Firefoxの出力では、有効な共有Chrome設定の`grouping`と`grouping_min`も保持しますが、Firefoxへの取込みではこの2項目を適用せず、既存の共有値を残します。保護条件は必須項目なので、欠けた入力を初期値で補って保護を落とすことはありません。

取込みの途中で失敗した場合に元へ戻せるよう、この端末に復旧用コピーを一時的に1件保持します。処理中・復旧待ちの間は元の設定で動作し、同じ拡張originの保存・切替・取込みは直列化します。読取りを保存処理の完了待ちにはしません。正常終了または復旧後は設定内容を含むコピーを除去し、読取りの世代を区別する機密情報を含まない識別子だけを残します。

復元処理自体も失敗した場合は元の設定での動作を維持し、「取り込む前の設定に戻す」を表示します。復旧が終わるまでは保存・切替・次の取込みを拒否します。復旧用コピーは拡張の再起動後にも読み取れますが、実ブラウザー再起動を含む組合せ検証は最終検証の対象です。このコピーを履歴やundoの永続化に使うことはありません。ブラウザー提供元や他端末からの同期書込みを排他するものではありません。

## メニューとバッジへの反映

設定の保存・外部変更による副作用はbackgroundの `storage.onChanged` で処理します。メニュー設定に関係する項目だけでメニューを更新し、バッジ設定に関係する項目だけで表示を更新します。並び順やURL文字列など、両者に無関係な変更では全メニュー再作成や全バッジ更新を行いません。

メニュー再作成は先行更新と子項目の完了を待ち、表示に使った設定snapshotをクリック時にも使います。再作成中または失敗した未完成のメニューではクリックを処理せず、説明と要求元タブのバッジの「!」で実行しなかったことを示します。生成に失敗した場合は、10秒以上たった後のタブイベントやクリックで作り直しを再試行します。詳細メニューのドメイン・scopeは公開済みの表示と対応します。バッジ設定変更は先行表示の完了を待って新しい設定を読みます。タブイベントの反映待ちとrevisionは `src/background/background-reflection.ts`、描画と通知timerは `src/background/badge.ts` が管理します。

[URLルールの構文・上限](pattern-matching.ja.md)と保存失敗の扱いは保持します。URL機能がOFFの場合、実行時に保存文字列を検証・照合しません。

## 検証の範囲

Chromeのコールバックと `runtime.lastError`、FirefoxのPromise拒否、保存遅延、完了順序、Storage変更イベントを制御した実登録handlerのテストで確認します。両方向の組の競合、古い保存完了、保存失敗と再試行、保存後の外部優先、表示とクリックのscope一致を対象にします。実際のブラウザーアカウントによる複数端末の同期は未実施です。
