# URLルールのパターン処理

URLルールは Picomatch 4.0.7 に固定しています。通常の glob、複数行の OR 条件、行頭・行末の空白除去、空行の無視は維持します。各行は共通検証後に `makeRe(pattern, { contains: true, strictBrackets: true })` でコンパイルし、一致したタブIDを重複なくまとめます。`contains` はURL全体との完全一致ではなく、パターンが一致する部分を含むかを調べる設定です。

## API と構文

製品の TypeScript・Vite では `import { isMatch, makeRe } from "picomatch"` を使えます。ネイティブ Node ESM で使う場合は CommonJS の default export を import し、そこから関数を取り出します。`makeRe(pattern, options)` は正規表現、`picomatch(pattern, options)` は再利用できる照合関数を返します。[APIとオプション](https://github.com/micromatch/picomatch/tree/4.0.7)を参照してください。

対応する構文には `*`、`**`、`?`、文字クラス、POSIX文字クラス、`{docs,help}` の選択、`@(foo|bar)` などの extglob があります。区切り `/`、ドットで始まるセグメント、バックスラッシュによるエスケープ、否定、大小文字は Picomatch の既定動作に従います。URLの `?` を文字として指定する場合はエスケープが必要です。正規表現の構文をそのままURLルールとして扱わないでください。

## 保存済みの拡張globと入力検証

修正版では、危険な反復extglobを文字列として照合する場合があります。たとえば `+(a|aa)`、`+(*|?)`、`+(+(a))`、`*(+(a))`、`+(+(+(a)))` は従来の反復条件として使えません。安全に単純化できる一部の構文は文字クラスに変換されます。これは[上流のReDoS修正](https://github.com/micromatch/picomatch/commit/5eceecd)の仕様です。本更新は保護を無効化せず、保存済み文字列を書き換えません。

入力画面と実行前は `src/rules/url-rules.ts` の `compileURLRules` を共用します。保存済みの危険な反復extglobを文字列として黙って採用せず、対象行と理由を表示します。修正して再保存するかURL機能をOFFにするまで、一括閉鎖を開始しません。保存済み文字列は書き換えません。`maxExtglobRecursion: false` は使用しません。

パターンの既定最大長は65,536文字で、超過時は `SyntaxError` になります。`makeRe` の成功だけでは、危険なextglobが元の意味で使えることを保証できません。上流は危険な構文を文字列へ変換するためです。厳密な入力検証には `strictBrackets: true` による括弧確認と、許可する構文・長さ・行数の明示が必要です。未知のPOSIXクラスもエラーになるとは限らないため、必要なクラスを別途確認してください。`@types/picomatch` 4系には最新の保護オプションがすべて定義されていません。型アサーションで保護を解除せず、製品側の検証で対応します。

## 製品で許可する構文と上限

有効なルールの保存時・読み出し画面・ボタンの一括処理前に、以下を同じ条件で検証します。エラーの行番号は空行を含む元の行番号です。

| 項目 | 上限・条件 | 超過時 |
| --- | --- | --- |
| 有効な行数 | 空白除去後の空行を除き100行 | 101行目のルールを拒否 |
| 1行の長さ | 空白除去後1024 UTF-16コード単位（絵文字は通常2単位） | 対象行を拒否 |
| 保存サイズ | 生文字列をJSON化したUTF-8バイト数＋キー `urlmatch_pattern` の長さが8192バイト以下 | ルール全体を拒否、保存データは変更しない |
| extglobの深さ | 16段以下 | 対象行を拒否 |

保存サイズには空行、行末・行頭の空白、JSONのエスケープも含みます。8192バイトは [Chrome sync Storage](https://developer.chrome.com/docs/extensions/reference/api/storage) と [Firefox sync Storage](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage/sync) の1項目の上限に対応します。共有領域の総量102400バイト・512項目、Chromeの書き込み頻度120回/分・1800回/時など、他の制限による保存失敗も従来のStorageエラー表示と再試行で扱います。この検証だけで保存成功を保証しません。この端末のlocalを選んでも、共有時の互換性を保つため同じ8192バイト上限を適用します。

`*`、`**`、`?`、文字クラス、波括弧の選択、`@(...)`・`?(...)`・`!(...)` はPicomatchの意味で使用できます。POSIXクラスは `alnum`、`alpha`、`ascii`、`blank`、`cntrl`、`digit`、`graph`、`lower`、`print`、`punct`、`space`、`upper`、`word`、`xdigit` のみです。閉じ忘れと未知のクラスを拒否します。単独の正規表現用括弧は許可せず、文字としての括弧は `\(`・`\)` でエスケープしてください。

反復extglob `+(...)`・`*(...)` は、空でないリテラルの選択だけを許可します。枝にバックスラッシュ、括弧、文字クラス、波括弧、`* ? + ! @` は使えません。枝の先頭が他の枝と重なる場合も拒否します。`+(foo|bar)`、`*(a|b)` は使用できますが、`+(a|aa)`、`+(*|?)`、`+(+(a))`、`*(+(a))`、`+(+(+(a)))` は対象行を修正する必要があります。この保守的な構文は上流が単純化できる一部のネストも拒否します。保存済みルールの意味を黙って変更せず、画面の行番号と理由から書き直してください。

保存失敗は下書きを残し、修正または「もう一度試す」を選べます。不正な保存済み有効ルールも設定画面で通知し、実行時はサービスワーカーのエラーログに行と理由を記録します。ボタン実行では閉鎖を含む一括処理を始める前に停止します。URL機能がOFFの場合、実行時は文字列を分割・検証・照合せず、他の有効な機能は動作します。OFFで保存する際もルール構文は検証せず、生文字列を保持します。ただしブラウザのStorage容量制限はOFFでも適用されるため、容量超過時は文字列を短くしてから保存してください。

## 依存監査の扱い

現行の製品用Picomatchは4.0.7、ビルド・テスト基盤はVite 8.3.5／Vitest 5.0.5である。依存構成は[package.json](../package.json)と[pnpm-lock.yaml](../pnpm-lock.yaml)を正本とする。現在はwebpack、ts-loader、copy-webpack-pluginを使わない。依存更新時は `pnpm audit` と `pnpm audit --prod` で全依存・本番依存を再確認する。

この文書は現行構成の監査結果を示すものではない。監査時は依存関係、取得日時、全依存・本番依存それぞれの指摘と対応を記録する。本番依存のHigh／Criticalが0件であることは、依存更新時の監査で確認する。過去のnpm／webpack構成での指摘を現行構成の残存指摘として扱わない。強制一括更新、監査の無視設定、危険な再現処理の無制限実行は行わない。
